# 종 추가하기

## 1. 후보 확인

- 추가할 종이 `FULL_SPECIES_LIST`(`js/data/species.js`)에 있는지 확인한다. 이 목록은 국립생태원 「국가보호종 지정현황」의 멸종위기 야생생물 282종이다.
- 새 종의 `name`은 `FULL_SPECIES_LIST`의 `n`과 **글자 하나까지 같아야** 한다 (공식 국명, 예: "점박이물범"이 아니라 "물범"). 이름으로 연결되기 때문에, 다르면 전체 종 목록에 "적합도 보기" 링크가 안 생긴다. 스모크 테스트가 검사한다.
- 해양수산부 보호대상해양생물(상괭이, 남방큰돌고래 등)은 환경부 282종 목록에 없다. 추가해도 되지만 `status`에 `해양수산부 보호대상해양생물`을 넣는다 (테스트가 이 문구로 예외 처리).
- 등급은 개정될 수 있다 (물범은 2022년 II급→I급). 기존 메모나 블로그가 아니라 최신 공식 목록 기준으로 적는다.
- 이미 `LAND_SPECIES`/`MARINE_SPECIES`에 있으면 중복 추가하지 않는다. 기존 종의 수치를 고치는 일이면 `update-species` 스킬을 쓴다.

## 2. 근거 조사 (생략 금지)

웹 검색으로 아래 항목을 찾는다. 우선순위: 국립생태원·환경부·국립생물자원관 자료 > 국내 학술 논문 > IUCN Red List > 해외 논문. 논문은 PubMed·Consensus 검색 도구가 연결돼 있으면 함께 쓴다.

- 학명, 멸종위기 등급(I급/II급), IUCN 등급
- 서식 환경: 기온 범위, 습도(또는 강수), 물과의 거리, 식생 밀도, 먹이, 인간 교란에 대한 민감도, 고도
- 해양종: 수온, 염분, 수심, 용존산소, 탁도, 먹이, 교란

**수치를 찾을 수 없는 항목을 추측으로 채우지 않는다.** 정성적 서술("하천 인근 습지", "해발 500m 이상 암벽")만 있으면 그것을 0~10 척도로 옮기되, 옮긴 근거를 사용자에게 보고한다. 핵심 항목의 근거가 전혀 없으면 추가하지 말고 사용자에게 알린다.

조사 결과는 출처 링크와 함께 사용자에게 요약해 보여준다.

## 3. 데이터 작성

`js/data/species.js`의 해당 배열에 추가. 기존 항목 형식을 그대로 따른다:

```js
{ id:'영문소문자', name:'국명', latin:'학명', code:'MA-08', status:'멸종위기 야생생물 II급 · IUCN 관심대상(LC)', habitat:'land', cls:'포유류', factors:{
  temp:{type:'range',lo:-5,hi:20,softness:15}, hum:{type:'range',lo:40,hi:80,softness:30},
  water:{type:'target',target:5,tol:5}, veg:{type:'target',target:7,tol:4,weight:2},
  food:{type:'target',target:6,tol:5}, dist:{type:'target',target:2,tol:4,weight:2.2},
  elev:{type:'target',target:5,tol:5} } },
```

- `range`: 실측 범위(기온·습도·수온·염분·용존산소). `softness`는 범위를 벗어났을 때 점수가 떨어지는 완만함. 같은 변수는 기존 종과 비슷한 값을 쓴다.
- `target`: 0~10 척도 변수. `tol`은 허용 폭.
- `weight`: 그 종에게 결정적인 요인만 1.5~2.6. 나머지는 생략(기본 1).
- `code` 접두사: 포유류 `MA`, 조류 `AV`, 파충류 `RE`, 양서류 `AM`, 어류 `PI`, 해양 포유류·거북 `CE`. 번호는 같은 접두사의 다음 번호.
- `cls`는 디지털 트윈 분류 필터에 그대로 나타난다. 새 분류를 쓰면 필터 칩이 자동으로 생긴다.

## 4. 3D 모양

`js/twin.js`의 `buildCreature(id)` switch에 `case 'id':`를 추가한다. 없으면 `default` 모양(둥근 덩어리)으로 나온다. 자세한 규칙은 `edit-creature` 스킬.

요약: 비슷한 체형의 기존 case(포유류 `fox`/`marten`, 새 `stork`/`owl`, 거북 `pondturtle`, 해양 `seal`/`dolphin`)를 복사해서 비율과 색만 바꾸고, 방향 있는 부품은 `putDir()`, 재질은 `twinMesh()`/`twinMat()`.

## 5. 화면 표기 갱신

종 수가 하드코딩된 곳을 고친다 (`grep -n "종" index.html js/core.js`로 확인):

- `index.html` 상단 eyebrow: `17종 · 2개 생태계`
- `index.html` 설명 문단: `육상·담수 13종, 해양 4종`
- `index.html` 전체 종 목록 안내문: `이 중 17종만`

(전체 종 목록 상단 요약 `dir-summary`는 자동으로 센다. 위 세 곳은 스모크 테스트가 데이터와 비교하므로 빠뜨리면 `npm test`가 실패한다.)

## 6. 검증

`check-site` 스킬을 따른다. 특히:

- 기본값(슬라이더 초기 위치)에서 새 종의 점수가 상식적인지 (근거 서식지 조건으로 슬라이더를 옮기면 80점 이상이 나오는지)
- 디지털 트윈 스크린샷에서 새 종 모양이 보이는지, 클릭하면 이름이 뜨는지
- 전체 종 목록에서 새 종 행에 "적합도 보기 →" 링크가 생기고, 누르면 해당 카드로 이동하는지
